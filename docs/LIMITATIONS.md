# Analytical and implementation limitations

- Data are synthetic. Forecast scores and recommendations do not establish production validity.
- Five menu items have invalid raw `Base_Price`. Cleaning flags these values but retains all 150 items because valid effective price history and positive transaction `Unit_Price` exist. Raw files remain unchanged.
- Menu groups are transparent multifactor business rules, not a supervised classifier or verified ground truth. Their evidence includes sales, contribution, ratings, repeat purchasing, wastage, promotions, and trends. New or short-history items receive an insufficient-history flag.
- Customer KMeans uses clean completed-sale RFM and profiled clusters. Labels are interpretations of those profiles; regional assignments apply the same trained global scaler/model to scoped RFM.
- Spark MLlib trains and evaluates Linear Regression, Decision Tree, and Random Forest on the same clean location-day series. The selected Random Forest is persisted and reload-tested in the pinned Linux Docker runtime; native Windows model saving still fails without Hadoop `winutils.exe`. The local Windows API job runner still invokes native Python, so a fresh job started there may be marked `COMPLETED_WITH_WARNINGS`. The fresh-process reload is a tested script, not yet wired into the live API forecast endpoint.
- The 581-case forecast comparison is a one-step-ahead backtest. Holdout lag features use previous observed holdout days, so it is not a recursive month-ahead forecast. Local Asia/Karachi calendar dates are used in the current cleaned version.
- The separate location/item/category forecasts use recursive 1, 7, 14, and 30-day predictions with no future actual demand fed back. One December test origin per eligible entity supports each exact-lead score, so category scores have only 10 cases. At lead 30, test MAE exceeds the seasonal baseline for all three grains (location 226.65 vs 128.95; item 26.68 vs 17.31; category 460.84 vs 257.90). These forecasts are `EXPERIMENTAL`; the longer horizons are not reliable operational commitments. Global item/category estimates include all locations and are withheld from regional accounts.
- Wastage records sample observed item/location/days; absent records are unknown, not zero. The shared feature builder leaves missing wastage and preparation as `NaN` and requires four observed weeks for a four-week wastage mean. The retrained model evaluates 6,149 observed holdout weeks and leaves 120,047 unobserved historical grid weeks unlabeled. Its amount MAE is 1.0035 versus last-observed baseline 0.6528; high-risk accuracy is 86.58%, precision 60.00%, recall 21.91%, and F1 32.10%. The model is `EXPERIMENTAL` and insufficient for unsupervised operational decisions.
- Raw `Pricing_History` contains two entries per item, but only item 6 has a genuine price change. Its equal 30-day windows show association, not causal price elasticity. Campaign before/during/after windows are likewise observational and may be confounded by seasonality or campaign selection.
- Basket rules are observational associations, not proven incremental bundle benefit.
- What-if outputs are estimates. The user supplies demand response; inventory/preparation changes use historical wastage assumptions, not an inventory simulator.
- Management writes to SQLite do not rewrite versioned historical Parquet. New menu, inventory, and promotion metadata need an explicit processing refresh before changing historical model inputs. Validated managed wastage records immediately affect live wastage, menu, location, promotion, executive, and what-if aggregates through an overlay. They remain separate from the Parquet used to train the wastage forecast, so its risk list is stale until an integrated retraining path exists.
- `GET /api/reports/*` serves historical legacy reports. Use `GET /api/exports/*` for current cleaned CSV/Excel outputs. The frontend uses current exports.
- Background jobs have queued/running/final status, logs, and audit events. They run as local subprocesses; there is no multiworker scheduler or real-time Spark-stage telemetry.
- Browser acceptance, large-scale load, availability, and security penetration testing remain unverified. Public repository, demonstration video, presentation, published blog, and human AI review evidence are outside this local workspace.
