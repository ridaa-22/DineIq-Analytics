# Runbook

Use the commands in the root README. Raw `data/raw/phase1-v1` is the input contract. `Python_Pipeline.build_processed` writes cleaned version `phase1-v1-clean-v3` under `data/processed/phase1-v1`. Its 959,964 clean completed sale lines are stored in `sales.parquet` and in 20 `sales_by_location/Location_ID=*/part.parquet` partitions. The partition manifest records each row count. Five menu items with invalid raw base prices remain in analytics because valid effective price history and positive transaction prices exist. Cancelled orders remain in validated orders but are excluded from sales and models. `quality_report.json` contains detected raw conditions, clean output counts, and applied rules. It does not list individual quarantined row IDs. Condition counts can overlap: a negative quantity can also make its discount exceed gross.

`spark_jobs.processed_sql` reads the partitioned clean sales and writes menu, location, and peak-hour aggregates to `reports/processed_spark`. Run Python and Spark forecast jobs independently after cleaning. Both use location-day demand with lag 1, lag 7, prior seven-day mean, location, day of week, and month. The chronological test cutoff is 2025-12-02; 581 later location-day cases form the shared holdout. `compare_location_forecasts` checks identical case IDs and actuals before writing `Models/integrated/dual_pipeline_comparison.csv`. Agreement means absolute prediction difference at most 50 demand units. Spark validates three algorithms and attempts native model persistence. A null `model_path` and non-null `save_error` in `spark_selection_metrics.json` mean the model was not saved.

`Python_Pipeline.train_customer_segments` fits one StandardScaler/KMeans model to cleaned RFM. It selects cluster count using sampled silhouette, profiles clusters before naming, then writes `customer_segments.parquet`, `customer_cluster_profiles.csv`, `customer_rfm_kmeans.joblib`, and metrics. `Python_Pipeline.train_wastage_forecast` builds prior-week-only item/location features and writes a saved estimator and next-week estimates. Review holdout recall in `Models/integrated/wastage_metrics.json` before using the high-risk list.

`scripts.seed_demo_accounts` creates local role accounts once and registers model versions; it does not invent job runs. Credentials are in ignored `data/demo_credentials.json`. The SQLite app database is `data/app_users.sqlite3` unless `DINEIQ_AUTH_DB` is set. Back up that file before administrative migrations. The app does not execute notebooks during API requests. Admin-triggered jobs run allow-listed scripts as background subprocesses and record queued, running, final status, duration, output tails, and audit events. A `COMPLETED_WITH_WARNINGS` Spark job can have valid predictions while its model was not saved.

For a quick check, request `/api/health`, sign in through `/app/Login.html`, change the executive location filter, open `/app/analytics-ml.html`, run what-if, and download a current export. Run the test commands in README. Management writes do not regenerate historical Parquet. Managed wastage additions affect live aggregates immediately but do not retrain the wastage forecast.
